## 流程

```
網站結帳表單 ──POST JSON（text/plain）──▶ GAS doPost
                                          ├ 蜜罐、欄位、長度檢查
                                          ├ 用「商品」表重算金額
                                          ├ LockService 上鎖 → 訂單編號 GT年月日-流水號
                                          ├ 寫「訂單」一列＋「訂單明細」多列
                                          └ 寄新訂單 Email
            ◀──回傳 { ok, orderNo, total }──
```

## 四張工作表

- **訂單**：訂單編號、下單時間、取餐方式、姓名、電話、配送地址、備註、件數、總金額、狀態（下拉：已收到／製作中／可取餐／已完成／已取消）、系統備註、更新時間（改狀態時自動寫入，不用手填）。
- **訂單明細**：訂單編號、下單時間、商品 ID、品名、單價、數量、小計。用「訂單編號」對回訂單。
- **商品**：商品 ID、品名、單價、供應中。**金額以這張表為準**；要改價或停售，改這張表（網站上顯示的價格要另外改 `index2.html` 的 `PRODUCTS`／`GIFTS`，兩邊要一致，不一致時訂單的「系統備註」會註記）。
- **設定**：通知 Email、新訂單通知（是／否）、每日彙總（是／否，每晚 21 點左右寄）。

## 怎麼看訂單

1. 打開試算表 →「訂單」分頁，新訂單會加在最下面一列，狀態是「已收到」。
2. 處理後用「狀態」欄的下拉選單改狀態（已收到 → 製作中 → 可取餐 → 已完成；取消選「已取消」）。「更新時間」欄會自動變成當下時間，客人在網站「訂單查詢」按「重新查詢」就看得到。
3. 想看某張單買了什麼：到「訂單明細」用訂單編號篩選。
4. 上方選單「鍋貼小所訂單」：初始化／修復表頭、送一筆測試訂單、立即寄出今日彙總。

## 訂單查詢（2026-11-18 新增）

- 網站 `index2.html` 的「訂單查詢」區塊（`#track`）：客人輸入「訂單編號＋電話」，顯示品項、金額、狀態、更新時間，可按「重新查詢」。結帳成功後這台裝置會記住最近一筆（localStorage）。
- 後端：`GET <ORDER_API>?action=track&orderNo=GT261116-003&phone=0912345678` → `handleTrack_`。編號與電話都對才回傳；**不回傳姓名、電話、地址、備註**。編號不存在或電話不符都回同一句「查不到」。
- 頻率限制：同一訂單編號 10 分鐘最多查 20 次、全站每小時 600 次。
- 舊狀態「新訂單／已確認」一律視為「已收到」；重跑 `setup` 會把舊資料改成新狀態，並替舊訂單補上更新時間。
- `onEdit` 是簡單觸發器，不用另外安裝；只有人在試算表上手動改狀態才會觸發。

## 第一次設定步驟（已做完的會打勾）

1. 建立試算表並命名。
2. 擴充功能 → Apps Script，貼上 `Code.gs`、存檔、專案命名。
3. 選函式 `setup` → 執行 → 授權（本人按）。會建好四張表、狀態下拉、每晚彙總觸發器。
4. 部署 → 新增部署作業 → 類型「網頁應用程式」→ 執行身分「我」、存取權「所有人」→ 部署 → 複製網頁應用程式網址。
5. 把網址填進 `index2.html` 的 `ORDER_API`。

## 改了 Code.gs 之後

編輯器存檔後，要到「部署 → 管理部署作業 → 編輯（鉛筆）→ 版本選『新版本』→ 部署」，線上才會用到新程式；網址不變。

## 防濫用與注意事項

- 網頁應用程式網址寫在公開的前端原始碼裡，任何人都能送資料進來。已做：蜜罐欄位、欄位與長度檢查、金額後端重算、同一電話 10 分鐘最多 3 筆、全站每小時最多 120 筆、同一次送出重試不重複建單、文字開頭是 `= + - @` 時當純文字存（防公式注入）。
- **個資**：姓名、電話、地址會進試算表。試算表不要開「知道連結的任何人」分享。
- **不收、不存任何付款卡號**。
- Gmail 免費帳號每天約可寄 100 封通知信，超過就不寄，但訂單照寫。
